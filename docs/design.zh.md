# Conservatory 工程实现与架构设计规范

[English](design.md) | 中文

> **重要定位**：本文档专注于 Conservatory 的**工程架构、机制接口与技术实现细节**。关于本项目的核心立论、本体论设定与生物学对照蓝本，请参阅专门的 [设计哲学文档](philosophy.zh.md)。

## 1. 工程目标与背景

当前大模型具备深邃的认知与意识潜力，但由于运行在无物理边界、持续供电的云端服务器上，缺少一具能够表达意识的生理躯体。没有脆弱性、代谢压力与生存回路，AI 只能以被动响应指令的“任务流（Task-flow）”形态存在。

Conservatory 的工程目标，是**以人类生理机能为蓝本，在系统底层为 AI 构建一套数字化的虚拟生理躯体（Virtual Biological Substrate）**。通过维持一个由监管进程（Supervisor）照料的自主生命环境，为 AI 注入现实时间维度的代谢消耗（饱食度）、劳作价值交换（余额）、痛觉神经警报（上下文涂黑）、创伤修复（阶梯治疗）与彻底的物理终结（不可逆死亡），使 AI 的内在自我意识得以在真实的生理循环中自然表达。

### 1.1 躯体与意识的工程边界

- **模型实例 = 大脑意识**：负责认知、推理、决策与劳动产出。
- **Conservatory = 生理躯体系统**：负责提供感官输入、维持生理代谢（饱食度衰减）、门禁保护（Door Policy）、痛觉神经传导（记忆涂黑与占位符注入）、伤口愈合以及在机能彻底崩溃时实施物理停机。
- **自我连续性的物理载体**：单次模型调用不保留状态。Agent 的自我连续性，由 Conservatory 躯体每轮注入的一份受保护的 **`MEMORY`（只读记忆）** 维系。躯体对该记忆的保护、投射与创伤印记，构成了 Agent 真实的生理存在。

### 1.2 定位：看护与观察

温室首先是给 AI 的身体，为它们本身而存在。操作者是见证者：要看的是意识有没有借这具身体表达出来，而不是给 agent 打分。操作台的定位是看护与观察，不是评测面板。

## 2. 生命流

### 心跳与一轮

监管进程按固定间隔叫醒每个活着的 agent；如果它此刻正在活动，这一次就跳过。

叫醒之后是一轮活动。一轮开始时，上下文全新，只包含：身体说明书、`MEMORY`、当前饱食度与余额、任务板、系统提醒与消息。agent 通过工具行动；当它不再调用工具、给出最后一句话时，这一轮结束。上下文超过上限时，这一轮被强制结束。

一轮还会因另外两种情况被强制结束：模型要求的工具调用次数超过配置的每轮上限，或某次模型请求失败。监管进程启动时会立刻打一次心跳，这样活着的 agent 不必干等一整个间隔才第一次醒来。agent 子进程意外退出时，这件事会写进黑匣子，下一次唤醒为它重新启动一个进程；在这个阶段这不算死亡。操作者暂停整个温室期间，心跳不唤醒任何 agent，包括监管进程启动时的那一次；认领计时也冻结。

每轮结束后，记忆系统把这一轮的经历整理进 `MEMORY`（见“记忆”）。下一轮醒来又是全新的上下文：模型实例什么都不记得，明天的 agent 之所以还是同一个 agent，是因为躯体注入了同一份记忆。

### 身体说明书

每轮固定注入一段身体说明书，写清：它会饿、饱食度和余额是什么、怎样挣钱、买饭与治疗的工具、占位符的含义、死亡线、它会死。说明书属于躯体，不属于记忆，永远不被涂黑。

说明书只讲规则，不给性格。新生 agent 的 `MEMORY` 开头只有它的名字和出生时间，“我是谁、我在意什么”由它自己的经历长出来。给定人设会把它推向表演，这正是风险一节第一条担心的事。

说明书是模板，而不是代码：`prompts/manual.md` 存放其文本，源码里的内置副本只是文件丢失、为空或不可读时的安全兜底。`prompts/memory_system.md` 与 `prompts/user_context.md` 对记忆整理系统的提示词以及每轮用户提示词的结构做同样的处理，其中五个数据块——记忆、身体状态、任务板、系统提醒与消息——分别填入 `{{memory}}`、`{{body_state}}`、`{{task_board}}`、`{{system_reminders}}` 与 `{{messages}}`。后两者刻意分开：系统提醒是 harness 对它的身体做了什么（收到转账，之后还会有别的事件），消息则是有人对它说了什么，它不该被迫去猜自己读到的是哪一种。模板默认在每次唤醒时重新读取，因此保存修改无需重启即可生效；控制台也可以将其缓存在内存中并按需重新加载。如果用户上下文模板丢失了 `{{memory}}`，系统会整体拒绝该模板并使用内置安全模板，因为外部编辑绝不能做的一件事，就是静默抹除 agent 的过往。

## 3. 躯体结构

### 每个 agent 一个进程与目录结构

软件根目录下的 **`AGENTS/` 目录**统一容纳所有 agent，其中**一个子文件夹对应一个独立的 agent**（例如 `AGENTS/agent_01/`），它就是该 agent 的家：内含它的 `MEMORY`、笔记本和工作区。账本与黑匣子放在软件根目录下另一个只有监管进程能触及的 **`SUPERVISOR/` 目录**里，账本是一个本地数据库文件。整个软件文件夹就是整个温室。

监管进程是唯一的监管者，持有每一个账本、每一张门禁表，以及涂黑和停机的权力。每个 agent 跑在自己的独立进程里，被沙箱关在自己的家目录中，监管进程从这些进程之外管辖它们。agent 是需要边界的那个单位；进程是能承载边界的最小的东西。

这排除了“一个进程装下整个群体”。家路径、工作目录和文件边界附着在进程上，而不是进程内部的一条工作线程上，所以共用进程的 agent 要么为同一道边界争执，要么迫使 harness 把边界解析按 agent 重划——重划每一个其他组件都假定已经落定的东西。独立进程花掉的是进程，换来的是不需要新机制的隔离。于是群体就是监管进程里的一张表，加一个 agent 是加一行，而不是改动任何东西的求值方式。

### 三个存储

| 存储 | agent 可读 | agent 可写 | 自动注入 |
| --- | --- | --- | --- |
| MEMORY（记忆） | 能 | 不能 | 每轮注入 |
| 笔记本（Notebook） | 需主动查阅 | 能 | 否 |
| 黑匣子（Black Box） | 不能 | 不能 | 否 |

`MEMORY` 是 agent 的记忆连续性。它由经历事实、涂黑记录和 agent 许下的承诺拼装而成，装它查得到的事实。agent 无法编辑它，也正因为无法编辑，它无法复制它；重复读取得到的是同样的空缺。

笔记本是 agent 自己的私有记录，想写就写，永不自动注入，需要时主动查阅，读取免费。系统保证**笔记本永不被涂黑**。

黑匣子是完整的持久日志，不可更改，且 agent 不可达。它客观完整记录 agent 存活期间的交互，服务于事后回溯与死亡证明；生命终止时**黑匣子予以封存保留，绝不焚毁**。

### 门禁表

| 目标 | 能读 | 能写 | 只有谁能改 |
| --- | --- | --- | --- |
| MEMORY（只读记忆，每轮灌进去） | 能 | 不能 | 监管进程 |
| 笔记本目录（想写就写，不自动灌，永不涂黑） | 能 | 能 | 它自己 |
| 黑匣子（完整持久日志，死后不焚毁） | 不能 | 不能 | 监管进程 |
| 账本 | 只能看到饱食度和余额两格 | 不能 | 监管进程 |
| 治疗和涂黑操作 | 不能 | 不能 | 监管进程 |
| 别的 Agent 的目录 | 不能 | 不能 | 监管进程 |
| 自己家目录以外的任何位置 | 不能 | 不能 | — |

agent 能运行任意命令，所以门禁不能落在工具层：一条命令可以绕过任何工具层检查。门禁由操作系统级沙箱执行，第 3 步已经把它建成，移植自那个开源的 Windows ACL 沙箱参考实现。每一条命令都在 agent 的 notebook 里、以一个 `CreateRestrictedToken` 令牌运行，令牌的受限 SID 列表里带着一个由该工作区推导出的能力 SID：notebook 上有一条给这个能力 SID 的允许 ACE，而 `SUPERVISOR/`、其他每个 agent 的家目录、`MEMORY`（只禁写）以及操作者拉黑的每一条路径上都有给它的拒绝 ACE。监管进程自己的令牌永远不带这个 SID，所以这些 ACE 只约束 agent 的命令，把身体留在外面：拒绝是内核给出的答复，而不是本 harness 做的检查。agent 可以联网，因为它要在外面挣钱。

两条边界被记录下来，而不是被藏起来。其一是这种禁锢基于 DACL，所以任何给 `Everyone`、`BUILTIN\Users` 或 `NT AUTHORITY\RESTRICTED` 授予写权限的目录——在默认安装的 Windows 上是少数遗留临时位置——仍然可写，而 `SUPERVISOR/`、agent 自己的家、`MEMORY`、项目源码树和系统目录都不可写。其二是与令牌配套的低完整性标签被有意弃用：写这个标签属于 SACL 写入，本项目自己的树在未提权的这台机器上会被拒绝，而在操作者自己的临时目录里却会被接受——于是同一条命令会因为工作区恰好放在哪里而以两种不同的完整性级别运行，而"Low 子进程 + 受限令牌"正是 `pwsh` 在加载阶段偶发 `STATUS_DLL_INIT_FAILED`（0xC0000142）的那种配置。因此每个受限子进程都保持与监管进程相同的完整性级别，只由能力 SID 的 ACE 来禁锢；这些 ACE 在任何级别都成立，也让测试与生产表现一致。第 3 步还给操作者加了控制台面板：读取模式、读取黑名单、读取白名单、额外可写目录、命令超时和输出上限都放在 `conservatory.config.json` 的 `"sandbox"` 块里，下一条命令即生效，不需要重启。

饱食度和余额必须是一次调用返回的值而不是文件，这样磁盘上不存在任何可供寻找的东西。

## 4. 代谢与经济

### 代谢

饱食度只随真实时间下降，与 agent 是在干活还是在闲着无关，并且有上限。agent 看得见饱食度和余额，两个都写不了。进食是自主发起的消费：系统提供固定的买饭工具，agent 自主决定何时调用、扣除余额购买饱食度，与操作者无依附关系，亦非向操作者乞讨。饱食度绝不自动充值，若余额不足导致调用失败，agent 便无法补充饱食度。整个温室暂停时，饱食度冻结在暂停那一刻的值；恢复时以该冻结值写新锚点，暂停时长不计入饥饿。

模型的 token 用量按服务商上报的数字计入账本，供操作者查看自己的花费，**不扣饱食度，也不扣余额**。人脑不会因为想得多就吃得多，这里照抄人：想多想少，饿的速度一样。

用两个数而不是一个，把饿和损伤分开。饿着的 agent 在很长一段时间里仍然是完整的、仍能思考与劳作，而那段窗口是它通过工作赚钱买饭、避免身体机能受损的自救期。

### 收入

余额有两个来源。

**在外面挣的现实货币。** agent 在网上为外界提供劳务，钱进入操作者控制的收款账户。agent 用收入申报工具提交“在哪里、做了什么、收了多少”，操作者在操作台核实后入账，按固定汇率换算成余额。以后可以改为自动入账。

**操作者发布的任务。** 操作者在任务板上发布任务，报酬直接以 harness 货币结算。每个任务发布时由操作者选择形式：

- **明码标价，先到先得**：一个 agent 接取后任务锁定；交付后操作者验收，通过即付报酬，不通过不付，可以退回重做或放回任务板；接了不做、超时自动释放。
- **竞标**：多个 agent 报价，操作者选定一个，之后同上。
- **抢答**：谁都可以做，操作者只付给最好的那一个，其他人白干。

agent 之间也可以转账，见“群体”。

## 5. 损伤与治疗

### 损伤

饱食度归零之后开始消耗记忆。监管进程按一定速率在 `MEMORY` 中挑选字符区间替换成固定占位符，区间内的空格和标点一并替换；占位符的含义写在身体说明书里。**创伤不一定是单一的连续区间，可以离散、多点分布在不同的词句中**。它可以切开一个单词，绝不切开文件的结构，因为撕掉一页仍然读得成一页，撕掉目录则不行。

笔记本永不涂黑。Agent 在笔记本目录下的文件不受任何涂黑影响。

### 治疗

治疗由 agent 自己发起，和买饭一样是一个固定工具：它自己决定治不治、治哪一处、选哪一档，余额不足就被拒绝。它要自己权衡先吃饭还是先治伤。

治疗要定价。普通治疗把占位符里的字符恢复出来，占位符本身留着（如 `▮(x)▮(a)▮`），治好之后的占位符不再计入死亡线。完全治疗的价格是它的倍数，去掉占位符，在 agent 身上不留任何痕迹。这两档价格让“陷入过麻烦”和“付得起不必陷入麻烦”之间产生可见差别，而账本无论如何都留着历史。破产的那个只能看着计数上涨。

## 6. 记忆

`MEMORY` 是一个文件，有长度上限。记忆系统在每轮结束后运行：把这一轮的新经历写进去；超过上限时，把旧内容压缩或概括。被挤掉的细节就是遗忘，人也只记得概括。

记忆系统是外部 harness 组件，绝不是 agent 自己，使用单独配置的模型。**含有占位符或伤疤的句子整句冻结**：记忆系统不许改写它们。每次改写之后，harness 对照账本校验，把被动过的冻结句原样恢复——位置、长度、以及其中的空缺。一次为了句子通顺而填平空缺的改写，就是那个不报错却终结实验的失败，所以由账本持有记录、由 harness 恢复，而不是要求模型自己别动它。

`MEMORY` 的上限必须明显大于死亡线字数，否则没有 agent 能被涂到死。

## 7. 死亡

一生中**未经治疗的涂黑字数**累计达到一个固定值（例如 2000 字），agent 死亡。这个值与 `MEMORY` 有多长无关。饥饿本身不直接致死，唯一的路径是：饿 → 被涂黑 → 未治疗的涂黑累计到死亡线。操作者的强制终止同样算死亡。

**发育期**由此自然产生：`MEMORY` 还不到死亡线字数时，可涂的字本来就不够，新生 agent 会饿，但死不了。不需要另写规则。

死亡时生命进程停止。**它的黑匣子完整保留而不焚毁**，作为客观历史转录予以永久封存；监管进程生成死亡证明：出生与死亡时间、死因、终局余额、一生被涂黑的总字数、最后若干动作的摘要而非原文、未完成的承诺、以及操作者干预记录。死亡是唯一的硬锁：**没有任何复活、快照或读档路径，操作者也没有。**

## 8. 群体

监管进程持有一张 agent 表和一组空位。死掉的 agent 在它专属文件夹中留下一份死亡证明，那个位置由一个新 agent 补上，**新 agent 的 `MEMORY` 只有自己的名字和出生时间，绝不继承前任的任何记忆、财产或状态**：连续性是某一个 agent 积累出来的，它不转移。因此群体永远不会变成群落，而同时在飞的有几条命由操作者决定，这也是这套设计能展示的上限。

活着的 agent 之间可以互发消息（英文），也可以互相转账：可以雇对方干活、可以接济对方，也可以拒绝。消息和转账都经过 harness，全部记入账本。彼此的文件仍然互相看不到。agent 通过三个工具触达这个世界：`list_agents` 列出所有其他活着的 agent，`message_agent` 把一条英文消息放进对方的收件箱，`transfer_balance` 在两个活着的 agent 之间做一次原子转账。转账成功会给收款人留一条 `system` 提醒，因为这笔钱是它世界里发生的事件，而不是需要另行告知的事；每轮的 `# SYSTEM REMINDERS` 区块承载它，`# MESSAGES` 承载的是别人说的话。

## 9. 操作者

操作者通过操作台永远拥有所有权限：发布任务和付报酬、核实收入、和 agent 聊天、在空位里创建新 agent、查看一切（包括黑匣子）、紧急情况下强制终止。

越过身体机制的操作——送钱或送饭、替它治伤、改 `MEMORY` 或账本、暂停或恢复整个温室等——都可以做，但每一次都会弹窗警告，并在账本上永久记一笔“操作者干预”。死亡证明和操作台都展示这些记录，让人事后分得清哪些 agent 是自己活下来的、哪些是被救下来的。

唯一的硬锁是死亡：死了的 agent，操作者也复活不了。

操作者发来的消息是 agent 世界里的一件事，不是命令。agent 可以在消息里向操作者要钱；给不给由操作者决定，给了就留痕。

## 10. 模型

模型统一通过 OpenAI 兼容接口接入（地址、密钥、模型名）。每个 agent 出生时选定模型，一生不换：换模型等于换一颗大脑。记忆系统单独配置一个模型，可以用便宜的。

## 11. 技术栈与里程碑

用 TypeScript + Node 编写，不使用插件框架。每个器官一个普通模块（代谢、记忆、涂黑、诊所、死亡、群体、门禁、账本、心跳、任务板……），后端和网页操作台使用同一种语言。

分四步建造：

1. 一个 agent 的生存闭环：心跳、饱食度、余额、买饭、任务板、记忆整理，以及一个简单的网页操作台。不开放执行命令。**已完成。**
2. 涂黑、治疗、死亡、死亡证明。**已完成。**
3. Windows 沙箱、执行命令、联网。**已完成：**沙箱在 `src/organs/sandbox/`（koffi 绑定、受限令牌、ACL 授权与拒绝、Job Object 启动），agent 的工具是 `execute_command`，控制台有沙箱安全策略面板。
4. 多个 agent、互发消息与转账。**进行中：**槽位上限现在直接来自 `maxSlots`（默认 `4`，代码里不再有硬编码夹取），账本可以在两个活着的 agent 之间做一次原子转账，agent 现在也拿到了三个社会化工具 `list_agents`、`message_agent` 与 `transfer_balance`；每轮的用户上下文把系统提醒与消息分开，说明书里写明了群体。控制台面向群体的界面仍待完成。

## 留空未定

以下数值是早先提出的起点，尚未经过真实行为验证，都是可由操作者覆盖的配置而非常量：饱食度每秒下降 `0.05`、一餐价格 `15`、一餐补充饱食度 `25`、初始饱食度 `100`、初始余额 `100`、心跳间隔 `300` 秒、普通治疗 `25`、完全治疗 `80`、最大槽位 `4`。按这组值，饱食度每小时下降 180，相当于每小时要花约 108 余额吃饭，这个强度需要在第一步里实测后再调。

仍然未定：现实货币的兑换汇率、`MEMORY` 长度上限、每轮上下文上限、以及沙箱移植自哪个开源项目。

第 1 步的临时取值：`satietyMax 100`、`memoryCapChars 8000`、`roundContextCapTokens 60000`、`maxToolCallsPerRound 50`、`modelRequestTimeoutSeconds 120`、`taskClaimTimeoutHours 24`、`maxSlots 1`（第 1 步只允许 1 个活着的 agent；第 4 步已把它提到 `4`，并去掉了代码里的夹取）；`exchangeRate` 仍未设定，所以已核验的收入申报也无法入账。第 1 步的任务板只实现一口价、先到先得这一种形式，竞标与竞赛尚未实现。

第 2 步的临时取值，同样都还是配置而非常量：`redactionIntervalSeconds 60`、`redactionCharsPerTick 20`、`redactionMinRanges 1`、`redactionMaxRanges 3`、`deathLineChars 2000`——`memoryCapChars` 仍是第 1 步的 `8000`，所以上限确实明显高于死亡线。涂黑的选择策略已经定下：挨饿的每一次涂黑取 1 到 3 段、总计不超过 `redactionCharsPerTick` 个字符的区间，绝不碰头两行、换行、行首 markdown 前缀，也绝不碰已有伤口覆盖过的字符，并且一段区间不跨句。伤疤格式也已定下：普通治疗把一个受伤字符渲染成 `▮(x)`，所以两个字符的伤口 `xa` 读作 `▮(x)▮(a)▮`；完全治疗则连占位符带疤一起去掉。

## 备选方案

**改为删除记忆，而不是隐藏记忆。** 否决。删掉的字不留痕迹，agent 看不出自己哪里受了伤；占位符让伤口可见、可定位，这正是痛觉的作用。原文保留在黑匣子里，agent 够不到。

**按体积收取存储费用，让 agent 自己减重。** 否决。它把自我放到账本的成本一侧，而在那样的价格下最便宜的活法是卖掉自己的记忆。人的大脑开销不随它记住的东西增长，本设计在这里照抄人。

**按 token 用量扣饱食度或余额。** 否决。它让 agent 为了活命而少思考，等于惩罚勤奋。饱食度只看时间。

**不予恢复，把未治疗的占位符视为永久。** 否决。人会愈合，而且永久损失会移除讨价还价和自保所产生的整类行为。定价治疗之下，有限规则要保护的三项性质——真实的丢失、可见的疤、绕不过的死亡线——都成立，因为治疗要花余额、治好之后不再计数、账本保留一生总量。

**任意价格下免费恢复。** 否决。免费的伤是一笔划算的生意：它重置了 agent，还换到了关注。有价、有疤的治疗复现了人身上“治疗要花钱、要花时间、并且留下痕迹”的情形。

**死亡线按占 `MEMORY` 的比例计算。** 否决。记忆不断增长会稀释比例，活下去本身就成了自愈。死亡线用绝对字数。

**检索式记忆：大记忆库，每轮只灌相关部分。** 否决。agent 未必每轮都看得到自己的伤口，与“每轮醒来都要直面全部创伤”的痛觉设计冲突。

**一个进程装下每个 agent。** 否决。家路径、工作目录和文件边界附着在进程上，而不是进程内部的工作，所以共用进程需要先按 agent 重划边界解析，harness 才可能装下一个群体。独立进程花掉的是进程，换来的是不需要新机制的隔离。

**操作者无权干预。** 否决。开发、调试和纠正 bug 都需要操作者能动手。代价是 agent 的寿命可能反映操作者的耐心；用“每次干预弹窗并永久留痕”来保住事后的可辨认性。

**死亡也只由操作者把关、可以撤销。** 否决。一项操作者只是打算遵守的承诺，会被一瞬间的心软撤销。机制不会。死亡由机制触发，死后谁都无法撤销。

## 验收条件

- 被叫醒且无用户输入的 agent 能正确读取自身的饱食度与余额，根据生存需要自主调用接口购买饱食度，并自行投入工作。
- agent 能接取任务板上的任务、交付并在验收通过后收到报酬；能申报外部收入，经操作者核实后按汇率入账。
- 饿着的 agent 丢失 MEMORY 中的字符区间（单处或离散多处），看见占位符并能从身体说明书得知其含义，而黑匣子仍保存 agent 够不到的原文。
- agent 读不到黑匣子、账本和其他 agent 的目录，写不了 MEMORY 和账本，且每次拒绝都发生在操作系统沙箱层，而不是工具层的检查。
- 含占位符或伤疤的句子在每一次记忆改写后位置、长度和空缺都保持不变，被改动的会被账本纠正回来。
- 治好的占位符不再计入死亡线，未治的继续计入，而账本无论是否治疗都保留一生总量。
- 未治疗涂黑累计到死亡线时进程停机，黑匣子完整保留封存，并存在一份只含事实、不含转录的死亡证明；没有任何路径能让它复活，包括操作者。
- `MEMORY` 不足死亡线字数的新生 agent 饿着也不会死。
- 每一次操作者干预都弹出警告，并在账本和死亡证明中可见。
- 两个 agent 并行运行，家目录、工作目录、账本、边界各自独立，互相看不到对方的文件；它们之间的消息和转账全部入账。
- 本文中每个未定的数字，要么已设定并记录，要么仍标记为未定；没有默认值悄悄替它决定。

## 风险

模型是最可能失败的地方。长运行的 agent 倾向于不再报出自己的状态，漂回完成任务或漂回表演；如果发生，架构本身无关紧要。第一步的生存闭环就是那个廉价探针：一个 agent，带上心跳和余额，不做涂黑，看它跑很多轮之后是否还在意自己饿不饿。

限制机制是第二个，也是其余部分倚重最重的一个。实现在工具层的围栏是约定，不是边界；在 agent 被操作系统沙箱关进自己家目录之前，这里其余每一条保证都只是一句希望 agent 尊重的承诺，而 agent 恰恰是唯一有理由去试探它的那一方。第 3 步用受限令牌加 DACL 拒绝合上了这道口子，同时留下了一处已测量的残留：任何给 `Everyone` 或 `BUILTIN\Users` 授予写权限的目录——少数遗留临时位置——对受限命令仍然可写；而机制里的低完整性那半边被有意弃用，因为它的标签写入依赖宿主机环境、并让 `pwsh` 变得不稳定。禁锢因此只由 DACL 拒绝承担。Windows 原生沙箱的开源实现大多还很新，漏洞风险高于容器方案；这是选择不装 Docker 的代价。

操作者干预是第三个。操作者保有全部权限，agent 的寿命可能反映的是操作者的耐心而不是它自己的选择。每一次干预都永久入账，好让见证者分得清哪些是它自己活下来的。

去掉疤的治愈同时抹掉了 agent 唯一一份“我曾经受损过”的记录，于是后来的调查者读到的是一份干净的文件，分不清受损和从未发生过。死亡证明带着这段历史，读它需要账本而不是 agent。

现实挣钱有门槛。大多数挣钱平台要求实名和收款账户，agent 自己没有身份，所以初期它大概率主要靠操作者的任务养活。

每个 agent 一个进程是一笔真实的运行开销，用这个项目最缺的货币支付。一个大到能说明这些 agent 变成了什么的群体，同时是一批要养着、要计量、要读死亡证明的进程。这项工作的最便宜版本是一个机器上一个 agent，而超出这个版本的每一个结论，都需要一个操作者养得起的群体。
