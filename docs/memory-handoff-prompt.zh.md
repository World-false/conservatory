# 记忆机制改造 · 独立执行任务书

> 本任务书**只做记忆机制**：MEMORY 两段式结构、增量追加、压缩、以及"如何不破坏涂黑（痛觉）和死亡线"。
> 与"请求体重排 / 配置数值 / 配置校验"无关，那些是另一个任务，请勿在本任务里做。
> 本任务也**不碰 `conservatory.config.json` 的数值**（那些数值由另一个任务负责改）。

---

## 背景（一段，先理解为什么改）

当前记忆系统每轮结束后，让记忆模型**一次性重写整份 MEMORY 全文**（`src/organs/memory.ts` 的 `consolidateMemory`）。目标 MEMORY 是 **750K token（约 300 万字符）**，但 DeepSeek-V4 单次输出上限约 **384K token**，所以全文重写**物理上做不到**。

解决思路（和 coding agent 改大代码库同理）：**不一次读全文、不一次吐全文，而是切碎、一块块来** —— 每轮只让记忆模型追加一小段；旧内容只在"该压缩"时才碰最老的一段。这样"记忆能长到 750K"和"每轮只吐几百 token"同时成立。

**最大风险：** MEMORY 文件同时被三个机制共享（记忆整理、涂黑、冻结句恢复）。涂黑是"按句子定点改写、按字符偏移记在账本上"的，任何重写或压缩只要动了含伤口（`▮` 占位符）的句子，就会让伤口偏移错位、重复计费或丢失，进而破坏死亡线。所以本任务的头号铁律是**保护涂黑/冻结句机制不被破坏**。

## 执行范围（4 项）

### 1. MEMORY 两段式结构 + 每轮带时间戳

把 MEMORY 文件格式定为：

```
Name: <名字>
Born: <ISO 时间>

# WHO I AM
（长期记忆：我是谁、在意什么、一直有效的承诺、一生大事。越老越压缩。第一人称。）

# RECENT ROUNDS
## Round N — <ISO 时间>
（这一轮发生了什么、做了什么决定、许了什么承诺。第一人称，2~4 句。）
```

- 头两行 `Name:` / `Born:` 是 harness 的，任何模型输出都不许带、不许改（复用 `enforceHeader`）。
- `# RECENT ROUNDS` 只保留最近 **10 轮**（做成具名常量，默认 10）。
- **每轮标题必须带准确 ISO 时间**，取 `RoundTranscript.startedAt`，复用 `isoTime`。
- 每轮块必须第一人称、只记事实与承诺，不记原始日志。

### 2. 增量追加 + 压缩（改造 `consolidateMemory`）

按 `docs/memory-mechanism.zh.md` 第 3 节的三步流程实现：

- **追加（append）**：每轮结束让记忆模型只输出"本轮新增块 `## Round N — <时间>`"，追加到 `# RECENT ROUNDS` 尾部。模型**不输出 Name/Born、不输出旧内容、不重写全文**。append 不碰冻结句，不需要恢复。
- **压缩（compact）**：当 `# RECENT ROUNDS` 轮块数 > 10 时触发。让模型把最老轮次中仍重要的事实/承诺并入 `# WHO I AM` 并输出新 `# WHO I AM`，删掉已并入的旧轮块。**只碰 `# WHO I AM` 和被并入的最老轮块，绝不许碰仍然保留的近 10 轮，绝不许碰含 `▮` 的句子。**
- **恢复（restore）**：compact 之后**必须**跑 `restoreFrozenSentences`（`src/organs/redaction.ts`），把被模型动过的冻结句按账本强制恢复。

**保留现有防线：** usage 缺失 / 模型报错 / 拒绝三条路径语义不变（拒绝时旧 MEMORY 不动）。

### 3. 涂黑 / 冻结句保护（本任务的头号红线）

- **绝对不改** `src/organs/redaction.ts` 的涂黑算法（`redactOnce` / `planRedaction` / `renderSentence`）。
- **绝对不改** `src/organs/ledger.ts` 的表结构、伤口字段（`wounds.offset/length/original_text/status`）、冻结句字段（`frozen_sentences.original`）。
- **绝对不改** `restoreFrozenSentences` 的算法，只确保它在 compact 之后被调用。
- 追加**不碰旧内容**（只在尾部加，不重写文件其余部分）。
- 压缩**不动近 10 轮、不动任何含 `▮` 的句子**，且事后 restore 兜底。

### 4. `prompts/memory_system.md` 改写

按 `docs/memory-mechanism.zh.md` 第 5.1 节改写记忆系统的 system 提示词，核心新增：

- 不再重写整份 MEMORY；只做两件事（由调用方在 user 里告知）：追加或压缩。
- 绝不输出 `Name:` / `Born:` 头两行。
- 绝不改动任何含 `▮`（U+25AE）占位符的句子，看见就原样保留。
- 第一人称；只记事实与承诺；不发明人设。

## 验收标准（做完自检这 6 条，全部成立才算完成）

1. 冻结句原文永不进模型能读的地方（被涂原文只存在于账本和黑匣子）。
2. 任何一次 append / compact 之后，冻结句的可见文本都等于 `renderSentence(original, wounds)` 的结果（位置、长度、空缺三样都对）。
3. 伤口计数只增不减、不重复；死亡线只由 `untreatedRedactedChars`（账本求和）决定，与 MEMORY 文件当前显示无关。
4. append 只在尾部加，绝不重写文件其余部分（头两行由 harness 管）。
5. compact 不动近 10 轮、不动含 `▮` 的句子，且事后跑 restore。
6. 空记忆/新生儿首次 append 能正确创建 `# WHO I AM` 和 `# RECENT ROUNDS`。

---

## 边界情况（执行前先想清楚，见规格 §8 全文）

1. 新生儿 / 空 MEMORY：只有 Name/Born，没有两个区块，首次 append 要能创建。
2. 追加后 RECENT ROUNDS 恰好 = 10：不压缩。
3. 压缩时冻结句在被并入的最老轮里：指令里明说"别动含 ▮ 的句子"，restore 兜底。
4. 涂黑落在 `# WHO I AM` 或 `# RECENT ROUNDS` 正文：标题行不是可涂单元，正文句才可能被涂，restore 必须全局跑。
5. 模型 append 时擅自输出全文或 Name/Born：裁剪到只保留一个合法轮块；非法则走"拒绝，旧记忆不动"。
